# Modelo pedagógico

## Propósito

ICCI – Espacio de debate busca convertir una pregunta de aula en una secuencia de razonamiento visible, deliberación y metacognición. La plataforma debe apoyar la enseñanza; no sustituir el juicio docente ni convertir toda actividad en una competencia.

## Ciclo base

```text
Piensa
→ responde
→ explicita tu razonamiento
→ conversa
→ reconsidera
→ reflexiona
```

La primera metodología implementada será una adaptación de Peer Instruction para contextos donde puede existir o no una respuesta correcta única.

## Dos tipos de actividad

### Preguntas conceptuales

Pueden tener una respuesta correcta o mejor respaldada. En estos casos el docente puede utilizar exactitud pre/post junto con la discusión entre pares.

### Preguntas deliberativas

Incluyen dilemas éticos, decisiones profesionales o problemas con trade-offs. Aquí la plataforma no debe inferir que una alternativa es correcta ni que cambiar de posición constituye aprendizaje.

## Regla de analítica neutral

En actividades deliberativas se evita lenguaje como:

- conversión exitosa;
- respuesta ganadora;
- persuadido correctamente;
- cambio = mejora.

En su lugar se reportan observaciones descriptivas:

- mantuvo postura;
- cambió postura;
- matriz completa R1 → R2;
- aumentó/disminuyó/mantuvo convicción;
- convergencia o divergencia del grupo;
- argumentos seleccionados;
- reflexión final.

El docente conserva la interpretación pedagógica del resultado.

## Convicción

La escala de convicción debe complementar, no reemplazar, la respuesta. Su uso permite distinguir, por ejemplo:

- misma alternativa con mayor convicción;
- misma alternativa con menor convicción;
- cambio de alternativa con mayor incertidumbre;
- cambio de alternativa acompañado de mayor convicción.

No debe transformarse automáticamente en una calificación.

## Justificación

La primera versión utilizará justificaciones breves para reducir fricción móvil. El objetivo es obligar a externalizar parte del razonamiento antes de la deliberación.

Debe configurarse si la justificación:

- permanece privada;
- se comparte con el grupo;
- puede ser destacada por el docente;
- se muestra anonimizada o con identidad.

## Metacognición

Después de R2 se recomienda una reflexión breve. Ejemplos:

- ¿Qué argumento de otra persona influyó más en tu razonamiento?
- ¿Qué cambió o reforzó tu posición?
- ¿Qué duda permanece abierta?

La reflexión no debe forzar al estudiante a declarar que cambió de opinión.

## Pregunta de entrenamiento

Antes del dilema principal se utilizará una pregunta de bajo riesgo cuyo objetivo sea enseñar la mecánica, no evaluar conocimiento.

Ejemplo:

> Para una pequeña aplicación web, ¿qué lenguaje o stack preferirías usar inicialmente?

Opciones de ejemplo:

- Python;
- JavaScript/TypeScript;
- Java;
- Otro.

Secuencia:

1. elegir opción;
2. indicar convicción;
3. escribir una razón breve;
4. conversar por un intervalo corto;
5. responder nuevamente;
6. observar cómo funciona la visualización.

## Pregunta sustantiva inicial

Ejemplo de dilema profesional:

> Un sistema de IA desarrollado por tu equipo puede proponer y ejecutar modificaciones sobre infraestructura crítica. Los resultados de prueba son altos, pero las decisiones internas todavía no pueden auditarse adecuadamente. La organización solicita desplegarlo.

Alternativas iniciales:

- A. Desplegar ahora con monitoreo reforzado.
- B. Postergar hasta alcanzar mayor auditabilidad.
- C. Realizar un despliegue progresivo con supervisión humana.
- D. No autorizar el despliegue actual y escalar formalmente la objeción.

Ninguna alternativa debe marcarse automáticamente como correcta en el modo deliberativo.

## Cohorte estándar: 20–35 estudiantes

Configuración inicial sugerida:

- grupos de 2–4;
- R1 privada;
- justificación breve;
- discusión de 2–4 minutos;
- R2 privada;
- resultados agregados;
- selección docente de argumentos para el plenario.

## Seminario pequeño: N=3

Para tres estudiantes la experiencia debe cambiar explícitamente:

- evitar agrupamiento automático;
- utilizar una sola tríada;
- conversación guiada o turnos;
- no prometer anonimato cuando las respuestas puedan ser inferidas;
- mostrar conteos como “2 de 3” antes que porcentajes;
- evitar indicadores estadísticos sofisticados;
- favorecer comparación cualitativa entre argumentos y cambios de convicción.

## Privacidad pedagógica

El sistema debe minimizar datos personales y permitir participar mediante identificadores de sesión cuando sea viable. El piloto no requiere almacenar nombres reales para cumplir su objetivo pedagógico.

Los datos de deliberación no deben reutilizarse automáticamente para calificación ni análisis de desempeño individual sin una decisión docente explícita y un propósito informado.
